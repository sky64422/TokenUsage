# TokenUsage 화면 가장자리 노치 전환 설계안

상태: 사용자 승인 후 구현 및 Windows 실물 검증 완료. 검증 범위와 남은 환경별 확인 항목은 아래 실행 기록을 따른다.

## 목적과 범위

사용자가 원하는 핵심은 CodeNotch처럼 화면 가장자리와 이어지는 아름다운 노치다. 링만 도입하거나 가장자리 부착을 후속 작업으로 미루면 이번 요구를 충족하지 못한다. Windows를 우선 대상으로 기존 Tauri 2 / Rust / TypeScript 위젯의 기본 화면을 노치로 전환한다.

이 문서에서 제안하는 기본값은 오른쪽 중앙, 세 공급자 링 상시 표시, 호버 상세다. 네 방향 배치, 상세 고정, 위치 복원까지 한 번의 전환 범위로 잡는다. 자동으로 아주 작은 손잡이까지 접히는 기능은 이번 범위에 넣지 않는다. 기존 플로팅 카드 화면을 선택 가능한 별도 모드로 유지하지 않는다.

## 시각과 상호작용

- 화면의 물리적 가장자리에 틈 없이 붙는 검은 면과 양끝의 오목한 연결 곡선이 핵심이다. 단순한 둥근 사각형을 화면 옆에 놓는 것으로 대체하지 않는다.
- 오른쪽/왼쪽은 세로, 위/아래는 가로. 기본 깊이 72 DIP, 링 지름 40 DIP, 선 두께 4 DIP, 셀 길이 72 DIP, 양끝 여유 각 56 DIP(연결 곡선 포함)를 적용한다. 첨부 이미지의 위아래 여유를 반영한 최종 치수는 DESIGN.md에 기록한다.
- 로고는 단색, 링과 숫자는 기존 위험도 색상과 판정 함수를 재사용한다. Pretendard와 숫자 고정폭을 유지한다. 면은 기본적으로 불투명한 검정이며 기존 투명도 설정과 텍스트 가독성 하한을 유지한다.
- 링 아래 사용률과 짧은 기간 표시를 둔다. 상세는 공급자명, 모든 기존 기간별 6px 바, 사용률, 리셋 시각을 표시한다. 상세 내부에는 기존 고정 열과 2px 바-숫자 간격을 유지한다.
- 링 호버/키보드 포커스 시 상세를 화면 안쪽으로 연다. 노치와 카드 사이 포인터 이동 경로에서는 닫히지 않는다. 영역을 벗어나면 180ms 후 닫고 재진입 시 취소한다. 타이머는 가짜 시계로 검증한다.
- 링 클릭 또는 Enter/Space는 해당 상세를 고정/해제한다. 다른 링 클릭은 고정 대상을 교체한다. Escape는 설정, 고정 상세 순서로 닫고 링으로 포커스를 돌린다. 호버로 다른 앱의 키보드 포커스를 빼앗지 않는다.
- 펼침/접힘 모션은 160ms, reduced-motion에서는 즉시 전환한다. API 조회를 모션 프레임이나 호버 이벤트에 연결하지 않는다.
- 설정 버튼은 노치 끝의 작은 단색 버튼으로 제공한다. 설정은 화면 안쪽 상세 영역을 사용하며, 기존 투명도·공급자·자동실행·로그·업데이트·종료 기능을 옮긴다. 설정 중에는 상세 자동 닫힘을 중지한다. 높이가 부족하면 설정 내부만 스크롤한다.
- 배치는 설정의 Edge와 Monitor로 선택하고, 드래그 핸들로 선택한 가장자리를 따라 이동한다. 키보드 방향키 이동도 해당 축으로 제한한다. 중앙으로 복원하는 동작을 제공한다.

## 데이터 의미

ProviderSnapshot과 직접 OAuth 조회를 그대로 사용한다. 링은 기존 backend가 선택한 `primary_used_percent`를 그대로 표시한다. 현재 backend는 기간별 최대 사용률을 primary로 선택한다. 주 기간 라벨은 공급자 adapter의 기존 primary 선택과 일치시킨다. 이 매핑을 구현 전에 확인하고 UI에서 별도 primary 정책을 만들지 않는다.

다른 기간이 기존 warning/critical 기준에 해당하면 작은 보조 상태 점과 접근성 설명으로 알리고, 상세에서 해당 기간을 확인할 수 있게 한다. 새 알림이나 토스트는 만들지 않는다. `null`/인증 필요/조회 불가는 `—`와 상태 표현을 사용하며 0%로 그리지 않는다. 초과 사용률은 숫자로 보존하고 링 길이만 100%로 제한한다. 세션 실행·대기 상태는 데이터가 없으므로 표현하지 않는다.

## 창과 배치 구조

Rust가 모니터 선택, 실제 창 위치/크기, DPI 변환의 단일 책임자가 된다. TypeScript는 노치 렌더링, 상세 선택, 포인터/키보드 상태와 필요한 콘텐츠 크기를 전달한다. 기존 `MutationObserver → set_content_min_size → resize clamp` 경로가 노치 크기와 경쟁하지 않게 교체한다.

우선 하나의 투명한 main 창으로 노치와 상세를 함께 렌더링한다. 닫힌 상태는 노치 크기만 사용하고, 상세가 열리면 화면 안쪽으로만 창 영역을 확장한다. 위치와 크기 적용 시 바깥쪽 접점은 유지한다. 시각적 곡선 바깥과 빈 상세 영역의 입력은 뒤쪽 다른 프로세스의 창으로 통과해야 한다.

이 방식의 입력 통과와 WebView2 투명도는 **첫 기술 검증 항목**이다. `pointer-events:none`이나 `WM_NCHITTEST`만으로 다른 프로세스까지 통과한다고 가정하지 않는다. OS 입력 처리와 창 크기 제한을 실측한다. 기존 코드의 `SetWindowRgn` 투명도 문제 주석도 재검증 없이 무시하지 않는다. 단일 창으로 기준을 못 맞추면 노치 창 + 필요한 때만 보이는 상세 창으로 분리하고, 그 실측 결과와 변경된 IPC/창 수명주기를 문서에 반영한 뒤 다음 단계로 간다. 노치 모양은 타협하지 않는다.

현재 `DWMWCP_ROUND`, 최소 240×120, 창 자유 크기 변경, 콘텐츠 높이 자동 맞춤은 노치에는 적용하지 않는다. OS 사각 클립 안에서 SVG/CSS가 연결 곡선을 그리도록 한다. 트레이 및 Ctrl+Shift+U는 노치와 열린 상세 전체를 함께 숨기고 복원한다. 포인터로 여는 상세는 비활성 표시, 명시적 키보드 호출/설정 조작은 필요한 포커스를 제공한다.

배치 계산은 물리 픽셀의 모니터 사각형과 해당 모니터 배율을 입력으로 받는다. 음수 좌표를 허용하고 DIP와 물리 좌표를 혼합하지 않는다. 모니터 식별 힌트, edge, 가용 길이에 대한 0..1 offset을 저장한다. 애니메이션 중간 창 크기는 저장하지 않는다.

노치는 실제 화면 경계에 붙인다. taskbar가 차지하는 구간은 가장자리를 따라 피하고, 상세는 작업 영역 안에 배치한다. taskbar가 선택한 가장자리 전체를 점유하면 그 배치를 사용 불가로 표시하고 가장 가까운 사용 가능한 가장자리로 옮기며 설정에 실제 배치를 알린다. 모든 가장자리가 사용 불가이면 트레이 접근을 유지하며 배치 실패를 진단에 남긴다. 자동 숨김 taskbar와의 접촉/재등장 충돌은 실제 Windows 시험을 통과해야 한다.

연결 해제된 모니터는 주 모니터의 사용 가능한 가장자리로 복원한다. 해상도·배율 변경, 절전 복귀 시 다시 계산한다. 기존 설정에 노치 필드가 없으면 기본 배치로 마이그레이션하고 공급자, 투명도, 자동실행, 단축키와 과거 window 필드는 보존한다. 기존 window 크기를 노치 크기로 쓰지 않는다.

## 제품 규칙 변경과 유지

변경: 기본 화면의 pill-only 규칙은 링 요약 + 상세 pill로, 8px DWM 패널 규칙은 노치 사용자 정의 윤곽으로, 항상 설정 높이를 유지하는 규칙은 화면 내부 상세 영역 사용으로 수정한다. AGENTS.md, PRODUCT.md, DESIGN.md, ARCHITECTURE.md를 구현과 함께 동기화한다.

유지: Claude/Codex/Grok 직접 OAuth, 5초 refresh, JSONL 추정 금지, AGY 제외, 알림 제외, Grok productUsage 미표시, opacity 가독성 하한, debug 자동실행 enable 금지, 서명키 git 제외. 공급자/API·업데이터 로직은 이번 UI 전환 대상이 아니다.

## 완료 기준

1. 네 가장자리에서 곡선 접점이 떠 보이거나 잘리지 않고, 실제 Windows 배경 위에서 검은 사각 프레임/흰 테두리가 없다.
2. 다른 앱으로 투명 영역 클릭이 통과하고, 링에서 상세로 이동할 때 닫힘·깜박임·포커스 탈취가 없다.
3. 100/125/150/200% 배율, 음수 좌표 보조 모니터, 모니터 제거/절전 복귀에서 화면 밖 유실이 없다.
4. 1/2/3 공급자, 0/정상/임박/100% 초과/결측/인증 오류, 긴 리셋 문자열 모두 표현 가능하다.
5. `npm test`, `npm run build` 통과 및 `npm run tauri dev` 실제 Windows 검증. 브라우저 캡처만으로 네이티브 검증을 대체하지 않는다.

## 구현 및 검증 기록 (2026-10-01)

단일 투명 WebView2 창을 사용한다. Rust의 곡선 hit test와 set_ignore_cursor_events로 빈 영역의 입력을 뒤쪽 창으로 통과시킨다. 창 위치와 크기는 Windows SetWindowPos로 함께 적용한다. 렌더링 치수는 Rust layout.metrics에서 SVG/CSS로 전달한다. 상세 최대 높이는 560 DIP이며 설정 콘텐츠만 스크롤한다. 양끝 여유는 각각 56 DIP다.

실제 Windows 100% 배율과 음수 좌표 보조 모니터에서 동작을 확인했다. 125/150/200%는 geometry/hit-test 자동 테스트로 검증했다. 혼합 배율 실물, 모니터 물리 분리, 절전 복귀, 자동 숨김 작업표시줄은 아직 실물 검증하지 않았다. 상세 결과는 docs/testing.md를 참고한다.
