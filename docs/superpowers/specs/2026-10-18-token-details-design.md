# Codex / AGY 토큰 상세 설계

작성: 2026-10-18. 상태: 사용자 설계 승인 후 Codex만 먼저 구현하도록 범위 축소.

## 현재 구현 범위 (사용자 후속 요청 우선)

- 이번에는 **Codex만** 구현한다. 아래 AGY 조사/설계 내용은 후속 확장 참고이며 이번 완료 조건과 구현 대상에서 제외한다.
- 기존 서비스 아이콘을 상세 사용량의 Provider 이름 앞에 추가한다. 그룹 한도에서는 서비스 헤더에만 아이콘을 표시하고 모델 그룹마다 반복하지 않는다.
- Codex 동작을 사용자가 확인하고 피드백한 후 다른 공급자로 확장한다. AGY 파일 수집과 CLI 설정 변경은 이번에 추가하지 않는다.
- 기간은 사용자 후속 요청에 따라 `오늘 / 이번 달`이다. 이번 달은 1일 00:00부터 현재까지다. 설정 탭의 이동 표시와 은은한 선택 광원을 재사용한다.
- 작업 중 한도 막대의 반짝임은 채워진 영역 안에만 둔다. 빈 구간 전체에 생기는 흰 그림자와 fill 바깥으로 번지는 광원은 제거하고 픽셀 회귀 검사로 확인한다.
- 모델 비중의 위치는 토큰 상세 내부가 아닌 **위쪽 메인 한도 막대**다 (사용자 정정 2026-10-18). 공식 한도 길이/%와 위험도 색 계열을 유지하며 채워진 부분을 모델별 기기 토큰 비중으로 나눈다. 구간은 1px 모서리의 네모 막대와 기본 2px 간격으로 구분한다. 아주 작은 사용량에서는 총 간격을 채움 폭의 25% 이하로 줄여 색 구간이 사라지지 않게 한다. 바로 아래 가깝게 한 줄의 작은 글씨(10px)로 색 점, 축약 모델명과 토큰 비중(소수점 최대 한 자리)을 둔다. `기기 토큰 · 집계 중` 앞 문구는 사용자 요청으로 제거하고 출처/비중 의미는 접근성 이름과 title에 남긴다. 해당 한도 리셋 시각에서 5시간/7일 전부터 현재까지의 입력+출력 기록을 사용하며, 모델별 한도 소모율로 제시하지 않는다. 가장 많이 쓴 모델이 가장 진하고 적게 쓸수록 같은 색 계열에서 밝아진다. 기록/리셋 정보가 없으면 기존 단색 막대를 유지한다. 토큰 상세에는 숫자만 남기고 기간 탭은 메인 바에 영향을 주지 않는다.
- 노치는 분할 구간과 작동 중 보조 링을 제거하고 단일 연속 원형으로 되돌린다. 사용률 숫자/위험도 색과 아이콘 강조는 유지한다.
- 상세 높이는 내용에 맞춰 자동 확장하며 작업 영역이 부족할 때만 본문을 스크롤한다. native canvas는 처음부터 가능한 높이를 확보하여 확장 시 노치와 HWND가 움직이지 않는다.
- 좌우 edge의 상세는 높이와 무관한 헤더 기준점을 유지하여 아래로 먼저 늘어나고, 하단 공간이 모자랄 때만 위쪽 공간을 쓴다. 상단 edge는 아래로, 하단 edge는 확보된 위쪽으로 펼친다. 드래그 중에는 고정 canvas 내부 좌표 변화도 계속 화면에 반영한다.

## 목적과 범위

사용자는 현재 상세 사용량에서 모델별 사용량과 CacheRead 등의 구성을 보고 싶어 한다. 우선 자주 사용하는 Codex와 Antigravity(AGY)를 지원하고 Claude/Grok는 다음 단계로 남긴다.

기존 한도 링과 한도 상세를 유지하고 그 아래 접이식 `토큰 상세`를 추가한다. 토큰 수는 CLI가 기록한 실제 사용량 필드만 집계한다. 구독 한도 소모율, 청구 금액, 누락된 토큰을 추정하지 않는다.

앞선 제안에서 사용자가 승인한 범위는 접이식 상세, 기간 선택, 모델별 토큰과 캐시 내역, 기기 내 기록이라는 출처 표시다. AGY의 모델명 및 비중 제한은 이번 조사에서 확인된 추가 제약이며 이 문서의 검토 대상이다.

## 현재 확인한 사실

- 현재 `ProviderSnapshot`과 `UsageWindow`에는 한도와 초기화 시각만 있다. 토큰 상세 수집 경로는 없다.
- Codex 최근 로컬 세션 4개를 제한적으로 조사하여 `token_count` 이벤트 166개와 `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `total_tokens` 필드를 확인했다. `turn_context.model`도 확인했다. 전체 사용량을 집계한 결과는 아니다.
- 설치된 공식 AGY의 `agy --sandbox --print-timeout 30s --print /usage` 실행은 성공했고 Gemini / Claude·GPT 그룹의 5시간·주간 한도 4개를 반환했다. 이 응답에는 토큰/캐시 항목이 없었다.
- AGY 로컬 `transcript.jsonl` 표본의 `PLANNER_RESPONSE`에는 `step_index`, `created_at`, `input_tokens`, `cache_read_tokens`, `output_tokens`가 있다. 조사한 기록에는 모델명과 CacheWrite가 없었다. `transcript_full.jsonl`은 같은 기록을 중복하며 더 많은 대화 내용을 포함하므로 읽지 않는다.
- AGY 표본 732개 중 706개에서 CacheRead가 input_tokens보다 컸다. AGY의 input_tokens를 Codex와 동일한 의미로 취급할 수 없다. 정확한 합산 의미를 증명하기 전에는 구성 비율을 계산하지 않는다.
- AGY 공식 status line 문서에는 모델명과 캐시 관련 메타데이터가 있다. 하지만 이를 수집하려면 별도 연동 및 설정 변경이 필요하므로 이번 단계에서 사용자의 AGY 설정을 수정하지 않는다.

## 선택한 접근과 대안

**권장: 기존 CLI 기록의 사용량 메타데이터를 읽는 별도 수집기.** 기존 한도 API를 유지하면서 Codex 모델별 내역과 AGY가 기록한 수치를 제공한다. 기록된 시점까지의 이력을 활용할 수 있고 CLI 설정 변경이 없다. 기기 밖의 사용과 삭제된 기록은 포함하지 못한다.

공식 한도 응답만 사용하는 대안은 변경이 작지만 이번 요청의 토큰/캐시 내역을 제공하지 못한다. AGY status line을 연동하는 대안은 현재 모델 식별에 유리하지만 별도 설치·설정과 중복 수집 방지가 필요하며 과거 기록의 모델명을 복원하지 못한다. 후속 확장으로 남긴다.

## 제품 데이터 정책

`PRODUCT.md`의 로컬 JSONL/토큰 원장 제외 항목에는 이번 사용자 요청에 한해 예외를 명시한다. `AGENTS.md`, `docs/providers.md`, `docs/ARCHITECTURE.md`에도 동일한 경계를 기록한다.

- **한도:** 기존 공식 OAuth / 공식 AGY `/usage` 데이터만 사용한다. 로컬 토큰으로 링이나 한도 %를 계산하지 않는다.
- **토큰 상세:** Codex/AGY가 기록한 사용량 메타데이터만 읽는다. 출처는 `이 기기의 기록`이다. 모든 기기/웹/계정의 전체 사용량이라고 표현하지 않는다.
- 허용 필드는 시각, 모델 식별 메타데이터, 사용량 숫자, 중복 제거에 필요한 기록 식별자다. 대화 본문·프롬프트·도구 인자·thinking·계정 이메일은 수집 결과, 캐시, 진단 로그, UI에 보관하지 않는다.
- 브라우저 스크래핑, 내부 비공식 AGY API, 모델 호출, tokscale, 단가 기반 비용 추정은 추가하지 않는다.
- 한도, 활동 상태, 토큰 상세는 서로 독립적인 상태로 유지한다. 한 쪽 실패를 다른 쪽 실패나 0으로 전환하지 않는다.

## 수집과 집계

새 책임은 `infrastructure/token_usage/`의 파일 수집과 `domain/token_usage.rs`의 순수 검증/집계로 분리한다. 기존 `providers/paths.rs`의 Codex 경로 해석을 재사용하고 AGY 경로는 현재 활동 감지에서 사용하는 `.gemini/antigravity*/brain/*/.system_generated/logs/transcript.jsonl`만 대상으로 한다. 자격 증명은 읽지 않는다. 새 의존성은 필요하지 않다.

수집은 백그라운드에서 수행한다. 한도 갱신, UI 첫 열기와 5초 refresh를 대량 파일 읽기로 막지 않는다. 파일별 읽은 위치와 집계 상태를 메모리에 보관하고 변경된 부분만 읽는다. 탐색/읽기는 작업량 예산을 두고 나눠 실행하며, 최초 스캔과 예산 초과는 `집계 중` 또는 `일부 기록`으로 명시한다. 일부 파일의 tail만 읽고 전체 기간 합계로 제시해서는 안 된다.

파일 위치가 세션 생성일로 나뉘어 있어도 최근 생성 폴더만 읽어서는 안 된다. 오래된 세션에서 오늘 발생한 사용량도 기록 시각으로 포함한다. 파일 축소/교체/복사, 재시작, 부분적으로 쓰인 마지막 줄을 처리하며 같은 사용량을 다시 더하지 않는다. `TOKENUSAGE_SKIP_DIRECT_QUOTA=1` 미리보기에서는 이 수집기도 실제 파일을 읽지 않는다.

기간은 로컬 시간 기준 `오늘`, `이번 달` 두 개다 (2026-10-19 후속 요청). 이번 달은 해당 월 1일 00:00부터 현재까지다. UTC 기록 시각을 로컬 날짜로 변환하여 필터한다. 날짜/월 경계에서 기존 집계를 재평가한다. 파일 삭제로 사라진 이력을 완전하다고 표시하지 않는다.

### Codex

- `turn_context` 등 구조적 메타데이터로 해당 사용량의 모델을 연결한다. 설정 파일의 현재 기본 모델을 과거 기록에 붙이지 않는다. 연결할 수 없으면 `모델 미제공`으로 분류한다.
- 누적 `total_token_usage` 이벤트를 합산하지 않는다. 증가분을 기준으로 한 번만 집계하고 반복된 동일 누적 보고는 무시한다. `last_token_usage`와 누적 합계를 함께 더하지 않는다. 모델 전환, 누적 카운터 초기화, 부모/분기/재개 시 상속 카운터를 구분한다. 근거가 없으면 해당 기여분을 보류하고 `일부 기록`을 표시한다.
- 입력과 출력, CacheRead, CacheWrite, 추론 토큰은 원본 필드를 보존한다. 누락된 필드는 `미제공`이며 0으로 채우지 않는다.
- 캐시 적중률은 `cached_input_tokens / input_tokens`다. 분모가 0이거나 값이 누락·모순이면 `—`다. 합계 비율은 모델별 비율의 평균이 아니라 합산한 분자/분모로 계산한다.
- 모델별 사용 비중은 해당 기간의 입력+출력 토큰을 기준으로 한다. 캐시 입력은 입력에, 추론 토큰은 출력에 포함되는 하위 항목이므로 중복 합산하지 않는다. 원본 `total_tokens`와 모순이면 임의 보정 없이 부분 데이터로 처리한다.
- CacheWrite의 입력 포함 관계가 확인되지 않은 스키마에서는 해당 수치를 별도 보조 값으로 표시한다. 확인되지 않은 네 개 구간을 합계 100% 막대로 만들지 않는다. 비중 막대는 입력/출력, 캐시 적중률은 별도 표시하여 이중 계산을 피한다.

### AGY

- `PLANNER_RESPONSE`의 시각과 실제 숫자 필드만 사용한다. `step_index`와 대화별 기록 소유권으로 중복을 제거한다. 동일 step 재기록은 최신 사용량 보고로 대체한다. 실패한 작업에도 소비 토큰이 보고될 수 있으므로 작업 성공 여부만으로 사용량을 버리지 않는다. 상태 문자열은 로컬 스키마 조사 후 실제 값을 기준으로 지원한다.
- 1차에서는 입력·출력·CacheRead를 원본 항목으로 표시한다. 모델 필드가 없으면 `모델 미제공`이며 Gemini/Claude 그룹 한도나 현재 선택 모델로 추정하지 않는다.
- CacheWrite, 추론 토큰, 모델별 사용 비중, 캐시 적중률 및 합계는 원본의 의미와 필드가 입증되지 않으면 `미제공`이다. AGY 원본 항목을 Codex와 억지로 같은 계산식에 넣지 않는다.
- 기존 그룹별 한도는 그대로 표시한다. AGY 한도와 이 기기의 토큰 기록은 독립적으로 갱신한다.

## UI와 데이터 전달

`ProviderSnapshot`에 선택적 `token_usage` 블록을 추가한다. 기본값 없음으로 역직렬화되므로 기존 fixture/AGY quota cache와 호환된다. 해당 블록은 자체 출처·갱신 시각·집계 상태·기간별 모델 행을 가진다. Claude/Grok에는 표시하지 않는다. 기존 `snapshots-updated` 이벤트와 초기 snapshot 경로로 전달하며 별도 공개 명령/이벤트는 필요하지 않다. 수집 완료 시 기존 `poll::notify_refresh()`로 전달을 앞당길 수 있다.

`src/ui/providers.ts`가 기존 한도 행 아래에 `토큰 상세` 열기/닫기를 제공한다. 열린 상태와 기간 선택은 공급자별로 메모리에 유지하며 5초 snapshot 갱신으로 초기화하지 않는다. 갱신 중 포커스/선택이 사라지지 않도록 DOM을 유지한다. 접기는 기본 상태다.

- 공통: `이 기기의 기록`, `오늘 / 이번 달`, 갱신 시각과 `집계 중 / 일부 기록 / 기록 없음 / 읽기 실패` 구분.
- Codex: 모델명, 토큰 수와 모델별 사용 비중, 입력/출력 구성, 입력 중 CacheRead 비율. CacheWrite와 추론 토큰은 하위 수치로 표시한다.
- AGY: `모델 미제공` 행의 입력·출력·CacheRead 수치, `모델·일부 항목 미제공` 안내. 지원하지 않는 비중 막대는 그리지 않는다.
- 명시적인 0은 `0`, 미제공은 `—`다. 긴 모델명과 큰 숫자는 가로 넘침 없이 표시한다. 외부 모델명은 HTML escape한다.
- 260 DIP 폭과 content_scale을 유지하고 내용 높이만큼 자동 확장한다. 화면 작업 영역만 최대 높이로 제한한다. 본문만 overflow 시 스크롤한다. 한도 행의 고정 열과 7px 바(사용자 두께 조정 요청 반영), Rust의 고정 native canvas, hover 비활성 창, 네 모서리 배치와 click-through를 유지한다.
- 토큰 상세를 연 뒤 설정으로 이동해도 세 탭의 공통 높이와 첫 열기 계약을 유지한다. 테마 3종, 불투명도 가독성, reduced motion을 적용한다.

## 검증과 완료 조건

집계 테스트는 실제 스키마를 본뜬 합성 fixture를 사용하고 실제 대화 내용을 저장하지 않는다. 다음 실패를 반드시 검증한다.

1. Codex 동일 누적 이벤트 반복, 모델 전환, 서브에이전트/분기/재개, 누적 카운터 초기화에서 중복이 없다.
2. AGY 동일 step 재기록 및 full 로그 중복 제외. 누락 모델/캐시 쓰기를 0이나 선택 모델로 바꾸지 않는다.
3. 명시적 0, 필드 누락, 음수·오버플로·모순 값, JSON 오류, 부분 쓰기와 파일 축소/교체를 구분한다.
4. 자정/월 경계, 오래된 세션의 오늘 사용량, 읽기 예산 초과, 파일 접근 실패와 초기 집계의 부분 상태를 검증한다.
5. 입력에 포함된 캐시와 출력에 포함된 추론을 중복 계산하지 않는다. 전체 캐시 비율은 합산 가중 비율이다. AGY에 검증되지 않은 비율을 표시하지 않는다.
6. 미리보기는 실제 파일을 읽지 않으며 수집 결과와 진단 데이터에 대화/도구/개인 정보가 없다.

필수 확인: `npm test`, `npm run build`, `python scripts/settings-smoke.py`, 토큰 상세 브라우저 smoke. 브라우저 smoke는 첫 열기, 접기/기간 선택 유지, 주기 갱신, 긴 모델명, 스크롤, unknown/zero/partial/error, 세 테마와 낮은 불투명도를 확인한다.

Windows 별도 프로필에서 native hover 안정성, 네 edge에서 상세 접기/확장, click-through, AGY 실제 한도와 Codex/AGY 메타데이터 읽기를 확인한다. 실제 사용량은 토큰을 새로 소비하는 호출 없이 기록과 대조한다. fixture 검증과 native 검증 결과를 구분해 보고한다. 서명 릴리스/설치와 Claude/Grok 확장은 이 구현 범위에 포함하지 않는다.

1차 완료는 Codex의 지원되는 모델별 내역/캐시 비중과 AGY의 제공되는 원본 수치를 실제 상세 패널에서 볼 수 있고, 미지원 항목이 명확하며, 집계/레이아웃 회귀 검증이 통과한 상태다. AGY의 정확한 모델별 분류와 캐시 비율을 완료했다고 표현하지 않는다.
