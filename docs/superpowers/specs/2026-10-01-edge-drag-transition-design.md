# 노치 드래그 방향 전환 설계

상태: 검토용 설계. 구현하지 않음. 기준 커밋: `0c32707`.

## 목적과 유지할 것

노치를 잡고 다른 화면 가장자리로 끌면 설정을 열지 않고 좌우 세로 노치와 상하 가로 노치 사이를 전환한다. 모서리에서 방향이 반복 전환되지 않고, 놓는 순간 보이던 위치가 저장되어야 한다.

사용자가 승인한 모양은 유지한다: 깊이 72 DIP, 공급자 셀 104 DIP, 양끝 inset 50 DIP, 연결 곡선 반경 36 DIP. 링 클릭 고정, 우클릭 설정, 5초 quota 갱신, 투명 영역 클릭 통과도 유지한다. 새 설정 항목이나 별도 이동 버튼은 추가하지 않는다.

이번 작업은 기존 동작 확장이지만, TypeScript의 단일 축 이동을 Rust의 화면 좌표 기반 드래그 세션으로 바꾸므로 상태와 IPC 경계를 포함해 설계한다.

## 선택한 조작 방식

1. **가장자리 진입 시 전환 — 채택.** 기존 가장자리를 따라 이동하다가 다른 가장자리 근처에 진입하면 그쪽에 붙는다. 화면 중앙에서는 마지막 유효 가장자리를 유지한다.
2. 항상 가장 가까운 가장자리 선택 — 화면 중앙이나 대각선에서 의도하지 않은 전환이 생겨 제외한다.
3. 화면 중앙에서 자유롭게 떠다니다 놓을 때만 부착 — 부유 상태와 별도 모양이 필요하고 드롭 결과를 늦게 알게 되므로 이번 범위에서 제외한다.

노치는 드래그 중에도 화면 가장자리에 붙어 있다. 중앙을 가로질러 반대편으로 이동할 때는 기존 가장자리에서 포인터를 해당 축에 투영한 위치를 따라가다가 목적 가장자리에 붙는다. 화면을 가로지르는 긴 창 이동 애니메이션은 넣지 않는다.

## 사용자 동작

- 왼쪽 버튼으로 노치의 빈 면이나 링을 누른다. 이동 전에는 기존 클릭 동작을 보존한다.
- 시작 지점에서 2차원 거리 5 DIP 이상 이동하면 드래그다. 시작 모니터 배율로 환산하므로 가로 방향으로 끌어도 시작된다.
- 드래그 시작 시 상세와 설정을 숨기고 hover 열기를 잠시 중지한다. 기존 고정 상세와 설정 상태는 기억한다. 놓거나 취소하면 새 위치 또는 복원 위치에서 다시 표시하되, 단순 hover 상세는 다음 진입 때 연다.
- 새 가장자리의 전환 영역에 들어가면 방향과 배치를 함께 갱신한다. 좌우는 세로, 위아래는 가로이며 글자와 로고는 회전하지 않는다. 공급자 순서는 유지한다.
- 놓으면 마지막 커서 좌표로 한 번 더 계산한 유효 배치를 한 번 저장한다. 드래그 뒤 click은 고정 동작을 실행하지 않는다.
- Escape, pointercancel 또는 예기치 않은 캡처 상실은 저장 없이 시작 배치로 복원한다. 정상 pointerup 뒤 발생한 캡처 해제는 취소로 해석하지 않는다.
- 우클릭 설정과 Shift+F10, 기존 방향키 이동은 그대로다. 방향키로 가장자리 전환하는 새 단축키는 이번 범위가 아니다.

## 전환 영역과 모서리 규칙

아래 수치는 구현 후 실제 드래그 영상으로 조정할 초기값이며 사용자 설정으로 노출하지 않는다.

| 항목 | 초기값 | 의미 |
|---|---:|---|
| 드래그 시작 거리 | 5 DIP | 클릭과 이동 구분 |
| 새 가장자리 진입 폭 | 64 DIP | 해당 물리 화면 경계에서 안쪽으로 측정 |
| 가장자리 전환 여유 | 16 DIP | 새 경계가 현재 경계보다 이만큼 가까울 때 전환 |
| 다른 모니터 진입 깊이 | 24 DIP | 연결 경계에서 왕복 전환 방지 |
| 시각 전환 시간 | 최대 160ms | 방향 변경 때 콘텐츠의 짧은 전환만 적용 |

현재 대상 모니터에서 사용 가능한 경계까지의 거리를 DIP로 계산한다. 새 후보는 진입 폭 안에 있고 현재 경계보다 16 DIP 이상 가까워야 한다. 동률이면 현재 방향을 유지한다. 후보가 여러 개면 가장 가까운 것을 선택하고, 현재 방향이 후보가 아닌 동률은 고정된 순서로 결정한다. 순서는 기존 fallback 순서인 right, left, top, bottom을 재사용한다.

예: 오른쪽 위 모서리 정확히 한 점에서는 right를 유지한다. 위쪽 경계를 따라 왼쪽으로 16 DIP 이상 이동하면 top으로 전환한다. 이후 오른쪽으로 되돌아오더라도 역방향 조건을 충족하기 전에는 top을 유지한다. 시간 지연 대신 공간 차이로 떨림을 막는다.

## 포인터와 노치의 위치 관계

처음 잡은 지점을 노치 길이에 대한 비율 `u`로 보관한다. 같은 경계를 움직일 때는 포인터가 잡은 지점과의 관계를 유지한다. 방향이나 배율이 바뀌어도 같은 `u`를 새 길이에 적용해 공급자 사이의 잡은 위치가 갑자기 중앙으로 바뀌지 않게 한다.

새 시작 좌표는 `포인터의 해당 축 좌표 - u × 새 노치 길이`다. 작업 영역 안으로 clamp한 뒤 기존 0..1 offset으로 변환한다. 가용 이동 길이가 0이면 offset은 0으로 정한다. 화면 끝에서는 clamp가 우선이므로 잡은 지점이 포인터와 정확히 일치하지 않을 수 있다.

## 다중 모니터와 작업표시줄

- 포인터가 다른 모니터 내부로 24 DIP 이상 들어가고 그 모니터의 유효 가장자리 진입 영역에 들어오면 대상 모니터를 바꾼다. 단순히 공유 경계에 닿는 것만으로 전환하지 않는다.
- 새 모니터에서는 그 모니터의 배율과 작업 영역으로 계산한다. 공유 경계의 left/right도 부착 후보가 될 수 있다. 모니터 사이 빈 공간에서는 마지막 유효 대상을 유지한다.
- 작업표시줄이 차지하거나 노치를 담을 수 없는 경계는 드래그 후보에서 제외한다. 막힌 bottom으로 끌었다고 다른 임의 방향으로 순간이동하지 않는다. 마지막 유효 배치를 유지한다.
- 기존 설정에서 Edge를 직접 고르는 동작의 fallback은 유지한다. 드래그 계산에서는 반환된 실제 edge가 후보 edge와 같은지 확인해 fallback 결과를 후보로 오인하지 않는다.
- 드래그 중 해상도·배율·모니터 구성이 바뀌면 세션을 취소하고 저장된 배치로 복원한다. 원래 모니터가 사라졌으면 기존 주 모니터 fallback을 사용한다. 이 자동 복원으로 저장된 사용자 배치를 덮어쓰지 않는다.
- 자동 숨김 작업표시줄 처리는 현재 OS 작업 영역 정보를 따른다. 숨김/노출 실물 검증 없이 지원 완료로 표시하지 않는다.

## 구현 책임과 상태

- `domain/notch.rs`: 기존 레이아웃과 hit test를 재사용한다. 같은 모듈의 순수 계산으로 후보 선택, 거리 차이, 잡은 비율, 정규화 offset을 처리한다. 입력은 물리 커서 좌표·모니터 목록·드래그 상태이며 OS나 저장소에 접근하지 않는다.
- `infrastructure/notch_window.rs`: 기존 컨트롤러와 32ms 커서 확인 루프를 확장한다. 네이티브 물리 커서 위치를 기준으로 삼고, DOM `screenX/screenY`를 모니터별 DPI와 섞지 않는다. 드래그 중 창 전체 입력을 유지하고 종료 시 기존 곡선 hit test로 복귀한다. 새 polling 루프를 만들지 않는다.
- `commands.rs`: 드래그 시작/종료/취소 전달만 담당한다. 기존 설정용 `set_notch_placement`는 유지하되, 프런트가 매번 placement를 계산해 보내던 드래그 preview 경로는 대체한다.
- `ui/app.ts`: pointer 캡처, 클릭 억제, 상세 상태 보관/복원, 오류 안내를 담당한다. 시작 요청은 pointerdown 시 보내어 Rust가 실제 시작 좌표를 보관하도록 한다. Rust가 임계값 통과를 알리기 전까지 일반 클릭으로 취급한다.

상태는 대기 → 눌림 → 드래그 → 종료다. 세션 ID로 늦은 이벤트를 무시한다. 종료/취소는 중복 호출해도 한 번만 처리한다. 드래그 갱신과 저장 완료가 역전되어 이전 preview가 되살아나지 않도록 같은 컨트롤러에서 직렬화한다. 눌림 상태로 놓으면 저장하지 않는다.

DOM pointerup 누락에 대비해 기존 네이티브 루프에서 버튼 해제를 확인할 수 있게 한다. pointerup과 네이티브 종료가 중복되면 같은 세션의 첫 종료만 유효하다. Escape/명시적 취소가 먼저 처리되면 이후 release는 무시한다. 캡처 상실이 버튼을 누른 동안 발생하면 취소하고, 정상 버튼 해제 이후라면 종료 처리를 따른다.

저장 실패 시 시작 배치와 입력 통과를 복원하고 기존 오류 표시로 실패를 알린다. 창 위치/크기는 기존 원자적 SetWindowPos를 사용한다. 네이티브 잠금 안에서 UI 스레드에 동기 왕복하지 않으며 이동 요청을 무제한 큐에 쌓지 않는다.

## 시각 처리

HWND 위치와 크기, 실제 노치 방향은 하나의 결과로 적용한다. 노치 모양을 회전·늘리면서 물리 경계에서 떨어지는 효과는 넣지 않는다. 공급자 콘텐츠에만 최대 160ms의 짧은 전환을 적용하고, 기존 및 신규 방향 전환이 겹치면 최신 결과로 대체한다. reduced-motion에서는 즉시 적용한다. 창 전환 때 흰 사각형이나 잘린 곡선이 보이면 시각 효과보다 원자적 배치의 안정성을 먼저 해결한다.

## 검증과 완료 기준

자동 검증은 2차원 시작 임계값, 네 방향 전환, 모서리 왕복/동률, 화면 중앙 유지, 두 모니터 진입, 음수 좌표, 100/125/150/200% 계산, 차단 경계, 1/2/3개 공급자, 이동 길이 0, 저장 실패, 중복 종료/취소/늦은 갱신을 다룬다. 시간 기반 테스트에는 fake clock을 쓴다. `npm test`, `npm run build`를 실행한다.

실제 Windows에서는 오른쪽→위→왼쪽→아래→오른쪽 이동을 영상 또는 연속 스크린샷으로 확인한다. 작업표시줄이 막는 방향은 유효한 테스트 환경에서 별도로 확인하고 차단 동작도 검증한다. 빠른 대각선 드래그, 원점 복귀, 창 밖에서 놓기, Escape, hover 포커스, 우클릭, 투명 클릭 통과와 다중 모니터를 함께 확인한다. 혼합 DPI·물리 모니터 제거·자동 숨김 작업표시줄은 가능한 실물 환경에서 확인하고 미검증이면 따로 기록한다.

완료 기준은 사용자가 승인한 72/104/50/36 비율이 유지되고, 모서리에서 왕복 떨림 없이 전환되며, 놓는 순간의 유효 위치와 재실행 복원 위치가 일치하는 것이다. 취소·저장 실패 뒤에는 입력 캡처나 임시 위치가 남지 않아야 한다.

## Implementation rulings

- Subsequent user instruction removes arrow-key repositioning entirely. Escape
  cancellation and Shift+F10/Context Menu remain.
- 24 DIP monitor-entry hysteresis applies only to crossed seams, not unrelated
  outside edges, so following the top edge across a monitor seam works.
- No extra content animation was needed: native placement is atomic and existing
  detail reveal/reduced-motion behavior remains. Accepted shape dimensions stay fixed.

- Subsequent user instruction explicitly permits bottom docking over the taskbar
  at the physical screen edge. Bottom is no longer excluded; other blocked edges
  retain their existing policy. Native bottom overlay is part of acceptance.
